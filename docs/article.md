# AI绘图工作台：从提示词到成品的一站式创作平台

## 项目简介

AI绘图工作台是一个全栈 AI 创作平台，整合了多家国内主流 AI 图像/视频生成服务，提供从提示词优化到成品输出的完整工作流。项目采用 Vue 3 + FastAPI + SQLite 架构，并通过 MCP（Model Context Protocol）协议实现了与 AI Agent 的无缝集成。

**核心定位**：让非专业用户也能用一句话描述需求，生成专业级的图像和视频内容。

---

## 为什么做这个项目？

在实际使用各类 AI 绘图工具时，我遇到了几个痛点：

1. **平台分散**：豆包、智谱、通义万相、可灵等平台各有优劣，但需要分别注册、配置、切换
2. **提示词门槛高**：写好英文提示词需要专业知识，中文用户很难直接上手
3. **知识碎片化**：优秀的提示词模板、案例、术语散落在各处，缺乏系统化的知识库
4. **缺乏工作流**：从创意到成品，中间需要经历多个工具和步骤

于是，我决定做一个「AI 绘图的 IDE」——把所有能力整合到一个界面里，让用户专注于创意本身。

                            │

## 核心功能

### 1. 多平台图像生成

支持 6+ 个图像生成模型，包括：

- **豆包 Seedream 4.5**：字节跳动出品，中文理解优秀
- **智谱 CogView-3-Flash**：免费额度，适合测试
- **通义万相 V1/XL**：阿里云出品，风格多样
- **DALL-E 3**：OpenAI 出品，创意性强
- **Stable Diffusion**：开源模型，可本地部署

用户只需描述需求，系统自动选择最佳模型，无需关心底层差异。

### 2. 多平台视频生成

整合了三家主流视频生成服务：

- **可灵 AI**：国内领先，性价比高（¥0.5-2/条）
- **即梦 AI**：字节跳动出品，中文理解好
- **Runway**：国际领先，专业级质量

支持文生视频和图生视频两种模式，自动生成 5-10 秒短视频。

### 3. 智能提示词优化

内置知识库包含：

- **术语词典**：200+ 个专业术语，涵盖风格、光影、构图、色彩等 7 大类
- **案例库**：100+ 个优秀案例，覆盖电商、品牌、社媒等场景
- **模板系统**：场景模板、节庆营销模板、提示词公式

用户输入中文需求，系统结合知识库自动优化为专业英文提示词。

### 4. MCP Agent 集成

通过 MCP 协议，项目暴露了 13 个标准化工具：

| 工具 | 功能 |
|------|------|
| `generate_image` | 根据提示词生成图片 |
| `generate_video` | 提交视频生成任务 |
| `edit_image` | 用自然语言编辑图片 |
| `search_knowledge` | 搜索知识库获取术语/案例 |
| `optimize_prompt` | 知识增强型提示词优化 |
| ... | 共 13 个工具 |

AI Agent（如 Claude、Cursor）可以直接调用这些工具，实现「对话式创作」。

### 5. 知识库系统

采用 SQLite + FTS5 实现：

- **自动种子**：首次启动自动灌入预置数据
- **全文搜索**：支持中英文混合搜索
- **向量嵌入**：基于 Embedding 的语义相似度计算
- **去重机制**：AI 入库时自动检测重复内容

## 关键技术决策

### 决策 1：后端作为统一代理

**问题**：各家 AI 平台的 API 格式不同，参数命名、返回结构、错误码都不一致。

**方案**：后端作为统一代理层，屏蔽底层差异。前端只需调用 `/api/generate`、`/api/generate-video` 等统一接口，后端负责转换为各平台的原生 API。

**收益**：
- 前端代码与具体平台解耦
- 新增平台只需修改后端，前端零改动
- 统一的错误处理和重试机制

### 决策 2：SQLite + FTS5 替代 Elasticsearch

**问题**：知识库需要全文搜索能力，但团队没有运维 Elasticsearch 的经验。

**方案**：使用 SQLite 的 FTS5 扩展，零运维实现全文搜索。

**收益**：
- 零部署成本，数据库就是一个文件
- 搜索性能满足需求（10 万条以内毫秒级）
- 支持中文分词（通过 jieba）

### 决策 3：MCP 协议集成

**问题**：如何让 AI Agent 能够使用这些创作工具？

**方案**：实现 MCP（Model Context Protocol）服务器，暴露标准化的工具接口。

**收益**：
- 支持 Claude、Cursor 等主流 AI Agent
- 工具定义自动生成，无需手写文档
- 支持 stdio 和 SSE 两种传输模式

### 决策 4：组件拆分策略

**问题**：随着功能增加，核心组件膨胀到 1000+ 行，难以维护。

**方案**：按功能模块拆分，每个子组件 100-200 行。

**实践**：
- `GeneratePanel.vue`（1100 行）→ 6 个子组件
- `ConfigModal.vue`（402 行）→ 3 个子组件
- `TemplateCenter.vue`（1100 行）→ 5 个子组件

**收益**：
- 代码可读性提升
- 团队协作更顺畅
- 单元测试更容易

## 开发过程中的挑战

### 挑战 1：多平台 API 适配

各家平台的 API 差异很大：

```python
# 豆包：POST /images/generations
# 智谱：POST /images/generations（但参数不同）
# 通义万相：POST /services/aigc/text2image/image-synthesis
# DALL-E：POST /images/generations（又是另一种格式）
```

**解决方案**：采用「Provider Adapter」模式，每个平台一个适配器，统一转换为内部数据结构。

### 挑战 2：知识库数据迁移

最初知识库是静态 JSON 文件，后来需要迁移到 SQLite：

**问题**：
- 前端直接 import JSON，改为 API 调用需要大量改动
- 数据结构需要兼容旧格式

**解决方案**：
1. 后端启动时自动从 JSON 灌入 SQLite
2. 前端逐步迁移，保留向后兼容的 getter
3. 最终删除静态文件，全部走 API

### 挑战 3：安全与权限

**问题**：API Key 如何安全存储？如何防止滥用？

**解决方案**：
- 后端 Key 模式：管理员在 `.env` 配置 Key，用户无需输入
- 前端 Key 模式：用户自己配置，存 localStorage
- 速率限制：基于 IP 的滑动窗口限流
- CORS 白名单：只允许指定域名访问

### 挑战 4：部署复杂度

**问题**：前后端分离部署，需要配置 Nginx、CORS、环境变量等。

**解决方案**：提供 Docker Compose 一键部署：

```yaml
services:
  backend:
    build: ./backend
    ports: ["8000:8000"]
  frontend:
    build: ./frontend
    ports: ["80:80"]
    depends_on: [backend]
```
